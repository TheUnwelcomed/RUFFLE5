# Ruffle on the PS5 — findings 2026-10-21 (addendum to claude/ruffle-ps5-plan.md §5l: the RADV archive and the phase-3a build)

## 1. The RADV archive builds on the server (2026-10-21, 16:17 MDT) — and what it took

`libvulkan_radeon.ps5.a` (272 MB, Mesa fork @1ba9874f, `tools/build-radv.sh release`) now builds on
the Bytesized host in 14 minutes, by `build-radv-server.sh` v14 (`ruffle-ps5-title/`). Facts worth
keeping from the fourteen versions:

- **mesa_clc needs an LLVM built for this libstdc++.** The LLVM 18 release tarball
  (`clang+llvm-18.1.8-x86_64-linux-gnu-ubuntu-18.04`) is compiled against GCC 7's libstdc++, which passes
  `std::optional` by reference where libstdc++ 11+ passes it in registers. Anything built on 22.04 that
  hands a `std::optional` into those libraries is miscalled — verified: `llvm::GlobalVariable`'s
  constructor read a pointer where the caller put the value, which is the mesa_clc segfault inside the
  SPIRV-LLVM-Translator. The tarball stays the PS5 target's clang/lld; the host tools link **LLVM's own
  Ubuntu 22.04 packages** (apt.llvm.org `llvm-toolchain-jammy-18`: libllvm18, llvm-18(-dev),
  libclang-cpp18(-dev), libclang-18-dev, libclang-common-18-dev, + tools for LLVMExports.cmake), unpacked
  with `dpkg-deb` under `ps5gpu/host/llvm18-deb`, relocated (Debian's llvm-config and LLVMConfig.cmake
  find everything relative to themselves). An ABI probe (that `std::optional` into `GlobalVariable`)
  gates the rest: `host LLVM check: ok`.
- **Compiling LLVM from source on the shared box took the server down** (v13: 16 parallel clang jobs,
  ~1 GB each, on a host at load 45 with 27 users). Every build now runs at `JOBS` (default 4) under
  `nice`/`ionice`, including Mihawk's `build-radv.sh` through a capped `NINJA=`, with a progress line a
  minute. `HOSTLLVM_FROM_SOURCE=1` keeps the source route at 2 jobs.
- Also needed, none packaged on the server: SPIRV-Tools v2025.4 (22.04 ships 2022.1), the translator
  v18.1.9 against that LLVM, glslang 16 (RADV's BVH shaders), python mako/pyyaml/packaging, cmake ≥ 3.22.1
  via pip; every pinned checkout is an explicit-ref fetch (the server's git rejects tag clones); the SDK
  used from here on is PS5_Vulkan's `.deps/native/ps5-payload-sdk` (upstream v0.42 + the platform layer).

## 2. Phase 3a build written (2026-10-21, 17:00 MDT): `ruffle-ps5-title/build-title.sh`

The whole title pipeline, joining the three proven pieces: the m1 target + shim (title mode),
ps5-rust-title's tail (converter, signer, PRX stubs, libc.prx, the import / raw-syscall / TLS gates) and
PS5_Vulkan's `tools/radv-link.sh` (RADV linked whole; libc++/libunwind/builtins; the platform layer's
heap in direct memory via `--wrap=malloc` & co, pthread/memstream wraps, `ps5_*` libc stand-ins via
`--defsym`, which override the shim's bodies at link time — RADV's own functions serve Rust too).
CRT/C++ runtime are PS5_Vulkan's copies (the CRT sets the IEEE FP state; a title starts with FTZ/DAZ).

`src/gpu.rs` is pinned to wgpu 30.0.1 / ash 0.38 from their sources (`Instance::from_raw`,
`expose_adapter`, `Adapter::open`, `from_hal`, `create_adapter_from_hal`, `create_device_from_hal`).
**wgpu 30 has no public way to adopt an application-made `VkSurfaceKHR`** (its only display-less route
wants a Linux DRM fd; `create_surface_from_vk_surface_khr` is `pub(super)`, on trunk too). So
`build-title.sh` fetches wgpu v30.0.1 into `vendor/wgpu` and applies
`tools/wgpu-hal-ps5-surface.patch`: eleven lines in wgpu-hal's Vulkan `create_surface` that accept the
handle through `RawWindowHandle::Gbm` (a single opaque pointer, no platform code); `Cargo.toml`'s
`[patch.crates-io]` points wgpu/wgpu-core/wgpu-hal/wgpu-types/naga at that tree. The mode chosen is
1920x1080 (VideoOut scales; 4K is the first mode). Ruffle itself is optional (`--ruffle`), so 3a
compiles none of it. Title `PPSA99620` "Ruffle"; log `/data/ruffle/ruffle.log`. Open: the first
server compile (cargo for the PS5 target) has not run yet; `rand`'s `getrandom` is a 3b item
(FreeBSD-11 libc has no `getrandom`; implement the custom backend over the platform's
`arc4random_buf`).

## 3. Phase 3a builds on the server (2026-10-21, 17:11 MDT): PPSA99620 "Ruffle", 28 MB eboot.bin

First Rust-side build against the real crates, four rounds, each a one-liner:
1. `build-std-features = ["panic_immediate_abort"]` — this nightly's `core` rejects it (`compile_error!`:
   it is a real panic strategy now). Dropped; m1's config never had it.
2. ash 0.38 has `StaticFn` at `ash::StaticFn`, not `ash::vk::StaticFn`. Everything else in `src/gpu.rs`
   (the wgpu-hal `from_raw` / `expose_adapter` / `open` / `from_hal` / `create_device_from_hal`
   sequence, the surface through the patched wgpu-hal) **type-checked first time**, and std, naga,
   wgpu-hal, wgpu-core and wgpu all compile for the PS5 target.
3. The link went through at once (109 MB ELF: std + wgpu + the 261 MB RADV archive + the platform
   layer); the import gate then listed ~900 `vk_common_*` / `wsi_*` names. **Mesa's dispatch tables
   reference every Vulkan entry point weakly; lld 18 exports each undefined weak reference as a
   dynamic import** (verified on a toy PIE with the tarball's lld), and the converter refuses imports no
   module exports. PS5_Vulkan's and PS5_RetroArch's titles link with
   `--no-dynamic-linker -z nodynamic-undefined-weak` for exactly this ("Mesa's weak entry points resolve
   at link time"); in lld 18 it is `--no-dynamic-linker` that keeps them out of `.dynsym` (the `-z`
   value only warns). The import check now reads `.dynsym` — what the converter sees.
4. Result: 381 imports, all exported by libkernel / libSceLibcInternal / libSceNet /
   libSceSystemService / libSceVideoOut and the generated libSceAgc / libSceAgcDriver stubs (2 + 3
   entry points: sceAgcInit, sceAgcSuspendPoint; sceAgcDriverSetHsOffchipParam, SetTFRing, SubmitDcb);
   no raw syscall instructions; no TLS; converted and signed (integrity valid), `eboot.bin` 28.9 MB.
   Not yet run on the console.

## 4. First console run of 3a (2026-10-21, 17:23 MDT): everything up to the adapter

`ruffle.log`: `sceAgcInit(8) from the title executable = 0`, `sceSystemServiceHideSplashScreen = 0`, the
Rust side started, the Vulkan instance was created on the static RADV, the physical device enumerated,
the `VK_KHR_display` surface made — and wgpu-hal declined to expose the adapter. The reason is in the
Mesa fork, `radv_physical_device.c` under `RADV_PS5`: *"No CTS release has passed on the PS5 yet
(PS5_Vulkan CTS_GAPS.md): the version stays 0.0.0.0 until one does"* — `conformanceVersion = {0}`,
and wgpu-hal hides a driver with conformance version 0 unless the instance carries
`InstanceFlags::ALLOW_UNDERLYING_NONCOMPLIANT_ADAPTER` (the MoltenVK opt-in). Set in `src/gpu.rs`;
a `log::Log` sink now writes wgpu-hal's debug lines (why an adapter is declined, which device
extensions are missing, what the swapchain does) into `ruffle.log`.

## 7. Ruffle runs on the PS5 (2026-10-21, 18:36 MDT) — milestone 3 reached

Three console runs of 3b, each stopped by one fact, each fact now in the kit:
1. `/data/ruffle/movie.swf` not found → the title now takes any `.swf` in `/data/ruffle/` or next to
   `eboot.bin`, and logs both listings.
2. `NullNavigatorBackend::with_base_path` → `Path::canonicalize` → `realpath` → **EPERM**: the
   console refuses `realpath` to a sandboxed title (milestone 1 had measured it). `shell/libc_fixes.c`
   defines a lexical `realpath` (absolute, `.`/`..` folded, existence checked with `stat`); an
   executable's own definition binds before the stub library's export.
3. Then: `loading /data/ruffle/movie.swf` → `AudioOut open: 48 kHz s16 stereo, 256-frame grains` →
   `pad services up, user 395971800` → `player built; entering frame loop` →
   `controller open (handle 57018112)` — **and the movie plays on the TV.**

So the stack of the plan's §3 exists and runs: `ruffle_core → ruffle_render_wgpu → wgpu 30 → wgpu-hal →
RADV (static) → VK_KHR_display on VideoOut`, with the DualSense as keyboard and mouse (scePad, Ruffle's
gamepad→key mapping; the touchpad as an absolute pointer) and sound through AudioOut from Ruffle's
mixer. Title build `bbb8f4e4…` + the realpath fix. What is still missing for the product (milestone
4): a drawn mouse cursor, a SWF picker instead of one fixed file, per-game key mappings, and the
measurements — frame pacing under a real game, AVM2 throughput, memory.

## 8. First real game on the console (2026-10-21, 18:46–18:52 MDT): what works, what was missing

The facts from the run (reported from the TV; the game is not yet named):
* The game loads and plays — "it actually ran".
* **The left stick moves the character**: the arrow keys reach the game, so the scePad read, the
  stick-as-d-pad merge and Ruffle's key path are all right.
* **The touchpad works as a mouse** — "title screens that require a mouse to start … it does work" —
  but **no pointer is drawn**, so there is nothing to show where it is hovering.
* The game's action (hitting the first enemy) did not happen: whatever key the game wants for it is
  not one the defaults send (Cross = Space, Circle = Esc, Square = Z, Triangle = X, L1/R1 =
  Shift/Ctrl, Options = Enter). Which key it wants is a property of the game, not of the title.
* "Sound was a bit strange" — no audio error in the log; the backend had a 256-frame (5 ms) grain,
  i.e. a 5 ms deadline for Ruffle's mixer (which decodes MP3 on that thread) against a renderer on
  the same two threads. Whether it starved is not in that log; the next one will say.

What this build (PS5_RUFFLE_V3) changes, each for one of those:
1. **A pointer is drawn** (`src/cursor.rs`): `CursorTarget` wraps Ruffle's `SwapChainTarget` and, at
   submit, appends a render pass that loads Ruffle's frame and paints an arrow (15 vertices in the
   shader, 5 instances: four black offsets for the outline, one white) at the pointer. Shown while
   the pointer moves or the touchpad is touched, hidden 3 s after (`cursor = on/off/auto`).
2. **The mapping is a file** (`src/controls.rs`, `controls.txt`): defaults ← `/data/ruffle/controls.txt`
   ← `/data/ruffle/<movie>.controls.txt`. A button may press several keys at once or click; sticks are
   `dpad` / `mouse` / `off`. Keys go to Ruffle as `PlayerEvent::KeyDown/KeyUp` with a distinct
   physical key per name (Ruffle drops a KeyUp whose physical key is not down), hold-counted so a key
   on two buttons is pressed once. New defaults: Circle = C, L3/R3 = A/S (Escape, which Flash games
   rarely read, is still bindable). Every line read and the mapping in effect go to `ruffle.log`.
3. **Audio grain 1024 frames (21 ms)** with fallback to 512/256 if the port refuses it, and a score
   line every 10 s: grains mixed, longest mix, mixes over budget, outputs refused
   (`audio: 469 grains of 1024 in 10.0 s; longest mix 1.84 ms (budget 21.33 ms), 0 over budget, 0 refused`
   is what a healthy run should print). `ruffle.log` writes are now serialised (the audio thread logs).

Not yet: the SWF picker; the game's actual key — needs the game's name (or a look at what it polls).
